Transaction và Cấu hình (Config) là hai khái niệm khác nhau hoàn toàn trong verification:
1. Cấu hình (Configuration - Việc bạn vừa làm trong test):
	- Giống như việc bạn thiết lập quy tắc trò chơi (Baudrate bao nhiêu? Có Parity không?).
	- Thường chỉ làm 1 lần lúc bắt đầu (hoặc thỉnh thoảng đổi).

2. Transaction (Class apb_transaction / uart_transaction):
	- Giống như quả bóng được ném đi trong trò chơi đó.
	- Dù bạn đã thiết lập quy tắc là "ném bóng tròn", bạn vẫn cần tạo ra hàng trăm, hàng nghìn quả bóng (Transaction) khác nhau để ném thử.
	- Mỗi Transaction chứa Dữ liệu (Payload) cụ thể (ví dụ: chữ 'A', số 0x54...) và các thuộc tính động khác (như Delay bao lâu thì gửi, có cố tình gây lỗi bit chẵn lẻ không...).
3. Tại sao vẫn cần Transaction class?
	- Để Randomize: Bạn cần sinh ra 1000 gói tin với dữ liệu ngẫu nhiên khác nhau để test kỹ, chứ không thể ngồi viết tay từng lệnh write(0x... ) trong file test được.
	- Để Abstraction: Monitor sẽ gói các tín hiệu điện áp (0/1) thành một object Transaction gọn gàng để Scoreboard dễ so sánh (Scoreboard so sánh 2 object Transaction với nhau chứ không so sánh sóng điện áp).
-> Tóm lại: Test cấu hình đường đua, còn Transaction là những chiếc xe chạy trên đường đua đó.
